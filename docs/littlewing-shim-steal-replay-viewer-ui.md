# LittleWing: How to build a replay viewer and clip editor

Report type: evaluation / review. It judges the LittleWing replay viewer against 5 popular open-source projects that solve the same user problem (watch a recording, find a moment, cut it out, export it), and prescribes UI behaviors to adopt, in payoff order. The comparison is about what the user sees and does. Stack and implementation appear only as evidence.

## Executive summary

The viewer can do the job, but you have to already know how. Every reference puts the recording's length, the playhead and your marks on one bar you can see and click. LittleWing puts a whole-second clock in the window title and nothing else. The biggest structural cost is the back seek: it restarts the process and replays from 0:00, and every scrubbing idea in this report gets worse while that stays true. LittleWing already wins on two things none of the references do. It marks a moment mid-game with Cmd-S, and it exports natively without the game's UI in the frame. The top finding, a timeline that shows marks, clips and the pending in-point, is the fix that every other finding hangs off.

### Key findings

1. **Put marks, clips and the in-point on one timeline, as asciinema-player, uosc, IINA and LosslessCut all do.** Points are dots or diamonds, ranges are tinted spans, and clicking any of them seeks there. Confidence: high.
2. **Design the scrubber around an expensive seek, as Slippi, uosc, IINA, LosslessCut and asciinema-player do.** Show the target time while dragging, seek once on release, let the newest target replace a queued one, and show a progress overlay during the wait. Confidence: high.
3. **Seek from periodic in-memory snapshots, as Slippi and asciinema-player do.** Slippi saves a state every 15 s and fast-forwards from the nearest one. This is the large item and needs emulator state save and restore. Confidence: medium.
4. **Drive the menu bar, tooltips and a `?` cheat sheet from one key table, as all five references do in some form.** A Replay menu in menu.m with key equivalents is the cheapest discoverability fix available. Confidence: high.
5. **Show controls on demand and keep them off the game, as asciinema-player, uosc and IINA do.** They fade in on pointer movement and hide after 2 to 2.5 s. Confidence: high.
6. **Use YouTube's seek grammar.** Arrows seek 5 s, J/K/L, comma and period step a frame, 0 to 9 jump by tenths. LittleWing's Right/Left for speed matches neither YouTube nor any reference. Confidence: high.
7. **Show what a key did on screen, and show the speed actually reached, as IINA and uosc do.** This replaces the title flash that freezes the clock. Confidence: medium.
8. **Treat a mark as a clip with no end, in one editable list, as LosslessCut does.** In, out, label, delete, undo and edge-drag to trim all work on one model. Confidence: medium.
9. **Give recordings a library and real ways in, as slippi-launcher and IINA do.** A document type, Open Recent, a browser with date and length, and "play from here" on each mark. Confidence: high.
10. **Name exports by time range, never overwrite, show progress with cancel, and reveal the file, as LosslessCut, IINA, uosc and Slippi do.** Confidence: high.

## Amendments, 2026-10-17

A review of this report against the issues and the source changed three things. The findings stand as written; these notes say where the plan now departs from them, and #30, #33, #34, #39 and #42 carry the same changes.

- **Right binds with the key table, in step 1** (Finding 6, #33). A forward seek doesn't restart the program, so Right goes ahead 5 s as soon as the table exists. Only Left, the back seek, waits for #59 and #42, and until then it flashes a message. Period and 0 to 9 can land early for the same reason if waiting on Left holds them up (#34).
- **The strip is drawn in window coordinates** (Finding 5, #39). Compute the game's letterboxed rect by hand in place of `SDL_SetRenderLogicalPresentation`, and draw the strip below it. It then stays 32 pt and crisp at any window size, the hit test is one rectangle on the raw event position, and `present` in src/display.c already draws one texture into one rect. Growing the logical area would scale and blur the strip's text with the window.
- **Scrubbing lands in two halves** (Finding 2, #42). The drag preview, seek on release, pause on press with restore on release, and newest target wins are right whatever a seek costs, so they go first. The progress overlay, the two-position display and the 300 ms and 500 ms thresholds are sized against a 90-second back seek, and wait for #59's measured number.

## Method

I profiled the subject first, at PR #29 (commit 2ab6ac3), through nine UI lenses: transport controls, timeline, seek feel, range editing, feedback and discoverability, control placement, library and entry points, export flow, and messes. A survey then searched for open-source projects whose UI solves the same problem in any stack. It confirmed each candidate's feature in its source, not its README, and shortlisted 5 of 12 verified candidates. Parallel dives read each reference at a pinned commit and cited every UI behavior to the file and lines that implement it. Synthesis grouped the behaviors several references share, mapped each to a named subject deficit, and ranked by deficit severity, then how many references agree, then adoption cost. A citation check opened every cited range in the pinned clones and every web page cited for closed products. 72 of 83 citations passed as written, and the 11 failures were corrected, none dropped. The per-idiom provenance step, which dates idioms by AI-authorship markers in commit history, was skipped by choice: it says little about UI paradigms. One reference, LosslessCut, ships an AGENTS.md telling coding agents to add commit trailers. The dive recorded it and did not act on it.

Closed products, cited to their vendors' pages and used as context only:
- YouTube's shortcuts set the grammar most users already know: K or Space pauses, J/L skip 10 s, arrows skip 5 s, comma and period step a frame while paused, 0 to 9 jump by tenths ([YouTube Help](https://support.google.com/youtube/answer/7631406)). - QuickTime Player's Edit > Trim shows yellow handles on a filmstrip. You drag them, then click Trim ([Apple Support](https://support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac)).
- Medal.tv cuts clips from a long recording with Start Trimming, then a "+ Clip" button, with clips of up to 2 minutes ([Medal support](https://support.medal.tv/support/solutions/articles/48001159728-how-to-create-clips-from-a-long-recording)).

Steam's timeline and NVIDIA's Instant Replay came up too. Their public pages describe developer APIs and "save the last 30 s" but not the clip-editing UI, so this report draws nothing from them.

## Baseline: where the subject stands

LittleWing is a C program with an Objective-C sliver for AppKit and AVFoundation. The viewer and the exporter are modes of the same `loony` binary, switched on by environment variables. The viewer has no on-screen controls and drops mouse clicks. Keys go in, and the window title is the only output. Playback re-runs the input log forward, paced to the wall clock.

Deficits the findings map to, worst first:

- **D1, no timeline.** Position is whole-second text in the title. The recording's length is never shown, though `scan_marks` reads the whole file and could keep it. Marks and clips are invisible (src/watch.c, src/replay.c).
- **D2, a back seek restarts the process.** `go_back` `execv`s and replays from 0:00 at about 8x. From minute 14 that is about 90 s, and the window closes and reopens (src/watch.c, src/main.c).
- **D3, no visible controls and undiscoverable keys.** Nothing lists the keys. Right/Left change speed, while J/K/L copy YouTube (src/watch.c `watch_key`, src/events.c).
- **D4, clips are append-only.** There is one in-point, and O saves at once. There is no adjust, nudge, preview, list, delete or undo short of editing `.clips` by hand (src/watch.c `save_clip`, src/clip.c).
- **D5, title-only feedback.** A message replaces the title for 2.5 s and freezes its clock. Full screen hides it. A desync closes the window without a word (src/display.c `display_flash`, src/replay.c).
- **D6, no way in from the app.** The viewer and the export need terminal launches. Recordings sit in a hidden folder, and Info.plist declares no `.lwreplay` type (src/main.c, tools/make_app.sh).
- **D7, export runs blind.** A second process runs with no progress, no cancel and silent overwrite, and nothing reveals the file. `-clip-N` names shift when the list changes (src/clip.c).
- **D8, the speed readout claims the speed requested.** HD at 8x falls behind but still reads "8x" (src/watch.c `pace`).

Strengths: every game records automatically at a few KB a minute, with retention that keeps marked, clipped and high-score games. Cmd-S marks a moment mid-game without the game seeing it. Export writes MP4 natively, with no ffmpeg, and checks output paths before the long seek. Exports and desync hashes read the emulated screen, not the window, so anything the display layer draws stays out of both. The clip list is plain text a person can edit.

## Detailed findings, ranked by payoff

### Finding 1: One timeline that carries marks, clips and the pending in-point

Four references draw the user's annotations on the same bar as the playhead, and make each one a seek target. asciinema-player draws markers as dots, filled once the playhead passes them. Hovering one shows `m:ss` and its label, and clicking seeks exactly there ([ControlBar.js:40-55](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/ControlBar.js#L40-L55), [ControlBar.js:135-152](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/ControlBar.js#L135-L152)). `[` and `]` jump between them ([recording.js:1180-1197](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/driver/recording.js#L1180-L1197)). uosc has the clearest vocabulary: point events are diamonds, ranges are tinted spans, and A/B points are half-brackets ([Timeline.lua:324-413](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Timeline.lua#L324-L413)). IINA puts loop points on the slider as shorter knobs, hidden until set ([PlaySliderLoopKnob.swift:38-93](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/PlaySliderLoopKnob.swift#L38-L93)), and hovering shows the time and chapter ([MainWindowController.swift:3056-3076](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/MainWindowController.swift#L3056-L3076)). LosslessCut renders clips as numbered colored ranges with tooltips ([TimelineSeg.tsx:14-200](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/TimelineSeg.tsx#L14-L200), [Timeline.tsx:435](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/Timeline.tsx#L435)).

This replaces the title clock in src/watch.c and src/display.c. The fix is a bar across the bottom showing elapsed and total time, Cmd-S marks as diamonds, saved clips as tinted spans, and a pending in-point as a bracket. Clicking a mark or a clip's start seeks there, and `[`/`]` jump between marks. Keep the end time `scan_marks` already reads. Confidence: high, four references draw the same thing.

### Finding 2: Scrubbing designed for an expensive seek

Every reference with a slow seek decouples the drag from the seek. Slippi moves only the thumb and the time label while you drag, and seeks once on release ([PlaybackSlider.cpp:30-128](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/DolphinWX/PlaybackSlider.cpp#L30-L128)). Its timer stops moving the thumb while a drag or seek is pending ([SlippiTimer.cpp:33-43](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/Core/Slippi/SlippiTimer.cpp#L33-L43)). uosc pauses when you press the bar and restores the earlier pause state on release ([Timeline.lua:137-175](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Timeline.lua#L137-L175)). IINA does the same and resumes only if it was playing ([PlaySliderCell.swift:173-189](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/PlaySliderCell.swift#L173-L189)). LosslessCut draws two cursors, a caret at the time you asked for and a line where playback actually is ([Timeline.tsx:74-84](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/Timeline.tsx#L74-L84)). A new request replaces the queued one, and the newest target runs when the current seek finishes ([useVideo.ts:35-81](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/hooks/useVideo.ts#L35-L81)). asciinema-player uses a generation counter so superseded seeks abandon themselves ([recording.js:1329-1362](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/driver/recording.js#L1329-L1362)), and puts a spinner over the frame during a load ([_overlays.less:54-67](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/less/partials/_overlays.less#L54-L67)). LosslessCut's working overlay shows the task, elapsed seconds, a percent and Abort ([Working.tsx:12-63](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/components/Working.tsx#L12-L63)). slippi-launcher waits 300 ms before showing a spinner, then keeps it up at least 500 ms so it never blinks ([use_delayed_loading.ts:15-50](https://github.com/project-slippi/slippi-launcher/blob/0930a2b66bdda78cebd0444c5e56249fea516cbe/src/renderer/lib/hooks/use_delayed_loading.ts#L15-L50)).

For LittleWing this matters more than for any reference, because every backward seek costs a restart today. A drag should move a caret and a time label only, and seek once on mouse-up. Pressing the bar pauses, and releasing restores the earlier state. During a long forward seek, show "going to 9:40" with a determinate bar, since the viewer knows the target frame, plus Esc to cancel. This replaces the title counter in `go_back` (src/watch.c). Confidence: high, five references converge, and the subject's cost structure makes it urgent.

### Finding 3: Seek from periodic in-memory snapshots

Slippi saves a full emulator state every 900 frames (15 s) on a background thread, stored as a delta against the first state. A seek loads the nearest keyframe at or before the target, fast-forwards without drawing, then restores the user's play or pause ([SlippiPlayback.cpp:165-206](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/Core/Slippi/SlippiPlayback.cpp#L165-L206), [SlippiPlayback.cpp:208-310](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/Core/Slippi/SlippiPlayback.cpp#L208-L310)). asciinema-player splits the recording into segments, each a snapshot plus the events after it, and a seek restores the nearest earlier one and replays forward ([segmented.js:132-195](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/driver/recording/segmented.js#L132-L195), [recording.js:1261-1281](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/driver/recording.js#L1261-L1281)).

This replaces the `execv` restart in `go_back` and `restart_watching` (src/watch.c, src/main.c). With a snapshot every 15 to 30 s, a back seek becomes a restore plus at most one interval of fast-forward at 8x, about 2 to 4 s. Issue #30 already flags it as the biggest piece. It needs whole-state save and restore in place, which the emulator can't do today, and it deserves its own issue. Confidence: medium. Two references converge, but the cost depends on emulator internals this report did not examine.

### Finding 4: One key table drives the menu bar, tooltips and a cheat sheet

IINA's menu items take their key and title from the key-binding table, so the menu bar is a live shortcut sheet ([MenuController.swift:879-1010](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/MenuController.swift#L879-L1010)). uosc reads each menu item's key from the bindings ([menus.lua:640-718](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/lib/menus.lua#L640-L718)). LosslessCut builds every tooltip as "Label (key)" from one table ([useActionTitle.ts:9-26](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/hooks/useActionTitle.ts#L9-L26)), and its Shift+? cheat sheet reads the same table ([KeyboardShortcuts.tsx:810-920](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/components/KeyboardShortcuts.tsx#L810-L920)). asciinema-player's `?` overlay pauses playback and hides keys the current source can't use ([HelpOverlay.js:3-71](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/HelpOverlay.js#L3-L71)). Slippi's strip under the game carries a permanent key legend that admits "Large fast-forwards might be slow" ([Frame.cpp:408](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/DolphinWX/Frame.cpp#L408)).

LittleWing's keys live only in `watch_key` (src/watch.c). Put them in one table that both `watch_key` and a new Replay menu in src/menu.m read, with key equivalents shown. AppKit then gives you a cheat sheet and Help-menu search for free. A `?` overlay can come later from the same table. Confidence: high, all five references teach keys this way, and the cost is small.

### Finding 5: Controls that appear on demand and stay off the game

asciinema-player reserves a 32 px strip below the content for its bar, so the bar never covers the frame. The bar fades in on pointer movement and hides 2 s after the last one ([Player.js:341-357](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/Player.js#L341-L357), [Player.js:450-491](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/Player.js#L450-L491), [_control-bar.less:1-18](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/less/partials/_control-bar.less#L1-L18)). uosc reveals by proximity, hidden at 120 px from the bar and fully shown at 40 px ([Element.lua:74-118](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Element.lua#L74-L118)). Away from the bar, the timeline shrinks to a thin progress line rather than vanishing ([Timeline.lua:47-87](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Timeline.lua#L47-L87)). IINA fades its bar out 2.5 s after the pointer stops, keeps it while hovered, and hides the cursor with it ([MainWindowController.swift:1257-1309](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/MainWindowController.swift#L1257-L1309)).

Issue #30 asks whether to draw over the game in SDL or use AppKit controls. The references favor drawing in the display layer, and LittleWing's exports and frame hashes already read the emulated screen, not the window, so an overlay costs nothing in clean output. I'd take asciinema-player's reserved strip in a window and uosc's thin always-visible progress line in full screen. Unlike asciinema-player, reveal the bar on transport keys too. Mouse events must reach the viewer instead of being dropped in src/events.c. Confidence: high, three references converge on show-on-demand.

### Finding 6: Seek keys with YouTube's grammar

asciinema-player maps Left/Right to 5 s, Shift to 10% of the length, 0 to 9 to tenths, and comma and period to one frame while paused. Keys with Cmd, Ctrl or Alt pass through to the OS ([Player.js:396-448](https://github.com/asciinema/asciinema-player/blob/fc82c581a10c6ae034517ad62323dea1a5ddb237/src/components/Player.js#L396-L448)). LosslessCut follows the video-editor convention: arrows seek, J/K/L control speed, comma and period step a frame ([configStore.ts:16-96](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/main/configStore.ts#L16-L96)). Slippi's legend reads Left Arrow rewinds 5 s and Period advances one frame ([Frame.cpp:408](https://github.com/project-slippi/Ishiiruka/blob/60f7b63496fb6ec7b9180a04f16f3edc0ad89fe2/Source/Core/DolphinWX/Frame.cpp#L408)). YouTube's documented shortcuts agree.

In `watch_key` (src/watch.c), move speed off Right/Left onto Shift+< and Shift+>, YouTube's speed keys. Make arrows seek 5 s, keep J/L at 10 s, add comma and period for a frame and 0 to 9 for tenths. Until Finding 3 lands, Left costs a restart, so pair this with Finding 2's progress overlay. Confidence: high, three references and YouTube agree, and the change is small.

### Finding 7: Show what a key did on screen, and show the speed reached

IINA shows "1:23 / 45:00" over a thin whole-file bar on every seek, from any input, and keeps it live while visible ([MPVController.swift:1152-1166](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/MPVController.swift#L1152-L1166), [OSDView.swift:113-130](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/OSDView.swift#L113-L130)). uosc doesn't show a text toast at all. A key press flashes the control it changed for 1 s ([Element.lua:162-173](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Element.lua#L162-L173)), and pause gets a centered glyph that grows and fades ([PauseIndicator.lua:22-80](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/PauseIndicator.lua#L22-L80)). uosc's remaining time is scaled by the current speed, so it tells you how long you'll actually wait ([main.lua:483-499](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/main.lua#L483-L499)).

This replaces `display_flash` in src/display.c, which freezes the title clock and is invisible in full screen. Once Finding 5's bar exists, flash the bar on any seek and the speed widget on any speed change. Show the speed `pace` actually achieved, not the one requested, so HD at 8x reads "5.2x" when that's the truth. Confidence: medium, the references agree on the goal but use different mechanisms.

### Finding 8: A clip list where a mark is a clip with no end

LosslessCut has one list. I past the current clip starts a new clip and O closes it. Backspace removes the end first, then the marker ([useSegments.tsx:374-388](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/hooks/useSegments.tsx#L374-L388), [useSegments.tsx:605-650](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/hooks/useSegments.tsx#L605-L650)). Shift-dragging a clip's edge on the timeline trims it ([Timeline.tsx:303-330](https://github.com/mifi/lossless-cut/blob/2610158c7861e0b96e2020cebcdd3c539ff33830/src/renderer/src/Timeline.tsx#L303-L330)). IINA's in and out knobs are draggable on the slider ([PlaySliderLoopKnob.swift:161-197](https://github.com/iina/iina/blob/7463aa128d792c85ff87d20376a29529a388ace8/iina/PlaySliderLoopKnob.swift#L161-L197)). uosc list rows label their actions with keys, such as "Remove (del)" ([Menu.lua:1661-1688](https://github.com/tomasklaen/uosc/blob/12b918fcbcae56ded0e073a965d769bb0c5d900e/src/uosc/elements/Menu.lua#L1661-L1688)).

## Where the subject already matches or beats the references

- Cmd-S marking during live play has no equivalent in Slippi, which records first and finds moments later from stats. No other reference records at all.
- Native MP4 export from the viewer is something Slippi's own users are still asking for in slippi-launcher issue #318. IINA has no trim or export at all (IINA issues #3487, #6067), and asciinema-player and uosc have none.
- Overlays stay out of exports and frame hashes by construction. Slippi needs a `--hide-seekbar` flag for external recorders.
- Separate I and O keys beat IINA's single key that cycles A, B, clear, which can't set B alone (IINA issue #4043).
- The "going to 9:40" title during a back seek, crude as it is, beats Slippi, whose picture, slider and label all freeze during a seek.
- Viewer messages already name the key that finishes an action ("a clip starts at 2:58: O ends it"), the same idea as LosslessCut's key-suffixed tooltips.

## Recommended execution order

1. **The cheap wins under #31.** Export naming, skip-if-exists, progress lines and reveal in Finder (Finding 10). A Replay menu fed by one key table (Finding 4). The `.lwreplay` document type and a Replays menu (Finding 9). None of these needs on-screen drawing.
2. **Key grammar** (Finding 6), in the same key table as step 1. It is small, but it moves muscle memory, so ship it before people learn the old keys. Right lands with the table in step 1; Left waits (see Amendments).
3. **The bar under #30.** The show-on-demand strip (Finding 5), the timeline with marks and clips (Finding 1), and on-screen feedback with the real speed (Finding 7). These touch the same display code, so do them as one piece.
4. **Scrubbing** (Finding 2) on top of the bar: drag previews, seek on release, newest target wins, a progress overlay with cancel.
5. **The clip list** (Finding 8), once the bar can show and drag ranges.
6. **Snapshot seeking** (Finding 3), as its own issue. Once it lands, revisit Finding 2's drag: with cheap back seeks, live scrubbing like asciinema-player's 50 ms throttle becomes possible.

## Refactor notes

- **Pure UI, no recording change.** Findings 1, 4, 5, 6 and 7 change only what the viewer shows and which keys do what.
- **Behavior changes that touch saved data.** Findings 8 and 10 change saved data, the `.clips` line format and export file names. Keep reading old `.clips` files. Never rename an existing export.
- **The large engine change.** Finding 3 changes the seek path, and the desync hashes must keep matching after a restore. Pin it with a test that seeks back across a snapshot and compares frame hashes against a straight replay.
- **Boundaries.** Nothing drawn for the viewer may reach `screen_rgba` or the frame hashes. Recording format and Cmd-S capture during play stay as they are. Replays are Loony Labyrinth only, so don't widen them to other games as part of this work.
- **Tests and commits.** The existing tests (tests/test_watch.c, tests/test_clip.c, tests/test_replay.c) are the invariant. Update them last, and only where a finding changes behavior on purpose. Verify and commit per step. Two consecutive failures on one step stop the work for a re-plan.
